# Structured local template creation

Use the absolute launcher resolved from the loaded Skill directory. Agent creation uses `./run templates create --input-json JSON`, or `--input-file -` with one JSON object on stdin. Do not drive the terminal wizard with a guessed sequence of answers. This creates local templates only; it does not authorize advertising writes.

Start with the facts already supplied. `{}` returns `missing_fields=["channel"]`; `{"channel":"qianchuan"}` asks for `template_kind=product|live`. Ask the user only for the returned missing business choices. Use `source_template="default"` for a requested new skeleton, or an exact source ID from returned `choices.source_template`. Do not select an arbitrary saved template.

Product example (IDs and names below are synthetic):

```json
{"channel":"qianchuan","template_kind":"product","source_template":"default","product":{"template_name":"示例商品模板","advertiser_id":"1001","product_name":"示例商品","product_short_name":"示例","product_ids":["2001"],"plan_name_template":"{product_name}-{creator_name}-{datetime}"}}
```

Live example:

```json
{"channel":"qianchuan","template_kind":"live","source_template":"default","live":{"advertiser_id":"1001","creator_name":"示例直播账号","aweme_id":"3001"},"delivery":{"budget":5000,"smart_bid_type":"SMART_BID_CUSTOM","roi2_goal":1.7}}
```

For either kind, `delivery` optionally overrides `budget`, `smart_bid_type`, `roi2_goal` or `daily_delivery_time` on the selected source. Preserve API units; do not assume an unverified currency conversion. Product short name and plan naming can retain domain defaults. Live display names and template IDs are generated by Core. All account/product/creator IDs are strings. Cross-channel fields, duplicate JSON keys and unknown properties are rejected.

`status=needs_input` never writes. `status=preview` returns the candidate, `state_version`, `preview_digest`, and the saved authorization coverage status. Show the candidate and obtain the user's approval to save it. Then repeat the identical JSON with `--submit --expected-revision REV --preview-digest DIGEST`, using the returned references. Changed input/configuration requires a new preview; `status=created` and `changed=true` confirm a local save. Do not retry a failed commit automatically. Existing authorization snapshots restrict advertiser selection; absent authorization permits drafting and is reported as unverified.

WorkBuddy does not provide this CLI capability; explain its unavailable local-template creation route instead of switching to Shell.
