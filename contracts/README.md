# Migration Contracts

This directory freezes the current Python CLI boundary before the Go migration.

- `commands.yaml` is generated by `scripts/acceptance/generate_command_manifest.py` and records all command dispatch prefixes, help text, parameters, exit codes, and hashes.
- `output/` contains JSON Schemas for the CLI envelope and mandatory Presentation object.
- `presentation/` contains byte-sensitive Markdown goldens for mandatory user-facing tables.
- `skill-evals/` contains semantic conversation cases, a model-driver protocol, and mandatory Presentation fixtures. The expected route is kept out of the model-driver payload.
- `state-compatibility.yaml` records the Python state, lock, credential, and cache contract used by the cross-runtime probe.
- `sdk-baseline.yaml` records the pinned official Go SDK and reproducible dependency evidence.
- `security/gosec-controls.json` binds every accepted Medium gosec heuristic to its exact module, rule, source-context fingerprint, Owner, Security reviewer, controls, removal condition, and expiry. New, changed, stale, expired, High/Critical, suppressed, or scanner-error findings fail verification; this inventory never grants Gate sign-off.
- `acceptance/g5-external-evidence-attestation.schema.json` defines the protected role-bound intake record for model, canary, Marketplace, rollback, and rollout evidence; every role has one fixed file set and cannot be substituted by a caller-selected workflow or artifact.
- `gates/` defines commit-bound G0 and G5 approval records plus the expiring write-canary authorization; every example is intentionally pending or expired and must never be treated as an approval.
- `p0-status.yaml` is the source for the deterministic G0 evidence summary and must list every unresolved blocker.
- `p1-status.yaml` records isolated-candidate P1 evidence separately from formal G1 approval; local green checks never imply `Go default`.
- `p2-status.yaml` records automated identity and account evidence while real dual-channel canary and owner approvals remain pending.
- `p3-status.yaml` records automated Shadow evidence for migrated read paths; it must not be interpreted as G3 approval while shared resilience, real canary evidence, native cross-platform CI, and sign-offs remain incomplete.
- `p4-status.yaml` records automated Shadow evidence for write paths and keeps AC-127, observation windows, and G4 owner approvals explicitly external and pending.
- `p5-status.yaml` records signed-candidate, launcher, rollback, synthetic journey, six-source aggregation, independent signoff, sealing, and publication automation without treating a dirty local build, implemented workflow, or fail-closed canary guard as G5 approval.
- `gates/ac127-write-canary.schema.json` defines the expiring commit-bound MT and SO authorization required before an explicit canary driver may start; the example is intentionally expired and pending.

Regeneration must run against a clean source revision. Review command additions, removals, help changes, defaults, and output changes before accepting the new baseline. Never store real credentials, account data, work links, or raw official responses here.

The executable P0 checks are:

```bash
scripts/acceptance/run.sh --suite baseline
scripts/acceptance/run.sh --suite state
scripts/acceptance/run.sh --suite launcher --candidate-dir path/to/candidate
scripts/acceptance/run.sh --suite contracts
python scripts/acceptance/build_g0_summary.py
python scripts/acceptance/verify_gosec_report.py \
  --report path/to/gosec-ocean-watch-go.json \
  --module prototype/ocean-watch-go
```

The `contracts` suite builds the isolated Go candidate, captures the Python
baseline, compares all global/domain/action help plus synthetic account behavior,
writes JSON and JUnit evidence, and scans the complete evidence tree for secrets.
Set `OCEAN_WATCH_EVIDENCE_DIR` to override its commit-keyed artifact directory.

`build_g0_summary.py` hashes every declared evidence file, records missing evidence
and a dirty working tree as blockers, and writes canonical `summary.json`. It exits
successfully for a blocked development summary; use `--require-ready` at the G0
Gate. Verify a completed approval only against those exact bytes:

```bash
python scripts/acceptance/verify_g0_signoff.py path/to/signoff.json \
  --summary artifacts/go-sdk-acceptance/p0/summary.json
```

The verifier rejects placeholder commit/hash values, summary tampering, unresolved
blockers, naive timestamps, missing roles, and fewer than two distinct approvers.

`--suite skill-eval` without `--driver-command` reports cases as `not_run` and
returns nonzero. Static CI may invoke `run_skill_eval.py --allow-not-run` after its
deterministic contract tests; a release candidate must provide a controlled model
driver and record its model, Codex, Plugin, commit, and reasoning identity.
