# alpha.1 首发范围与验收

文档属性：首个 V3 预发布版本的产品范围与发布、验收边界。范围初定于 2026-11-07，2026-11-08 发布准备明确版本为 `3.0.0-alpha.1`；本文不替代对应源码、测试和精确提交的验收证据。

本次按实验性快照发布：原 `main` 保留为 `2.0`，原 `V3` 成为默认分支 `main`。真实宿主和人工业务验收尚未完成，下述第 5 项仍为开放验收项，不以发布动作视为通过。GitHub Release 标记为 prerelease 且不替换正式 latest；完整 V3 Alpha 门禁继续独立报告。

## 首发范围

首发目标是在一个经过实际验收的宿主及独立 CLI 中完成千川作品批量预检、可信确认、创建/追加、结果对账与重启恢复。优先验收 macOS arm64 的本地 Broker；宿主的具体版本在验收时记录。既有查询能力继续保留，三项官方查询分页限制如实呈现。

`3.0.0-alpha.1` 提供上述链路的源码、隔离测试及随包运行时，尚不宣称任何宿主的真实业务闭环已验收。预算仍显示 `budget` 接口原值；金额单位与人类可读金额展示须在实际业务验收前补齐。Windows Broker 暂不可用；新建每组最多 100 条作品，摘要超过展示上限时阻断确认。

其他宿主、Windows Broker、营销和其他千川写入的统一迁移属于后续工作。未完成可信执行迁移的入口不得在首发范围内声称支持可信写入；预发布运行时必须阻断这些在线写入，而不是仅靠说明文字限制。预发布通过不等于 PRD M0–M5 或完整 V3 Alpha 验收通过。

## 发布检查与开放验收项

1. 版本、安装和升级链理解 `alpha.N`，Python 元数据使用对应的 PEP 440 表示；稳定安装不得自动选择预发布运行时。Tag、清单、包版本、CLI 版本及更新日志保持同一产品身份。
2. 千川执行仅接受持久化操作 ID、版本、摘要和已验证审批引用；模型布尔值、旧 `--submit` 或旧预检 ID不能替代 Broker 确认。展示内容由实际载荷及预期目标生成，确认期间不持广告主写锁。
3. 派发前重新核对目标、模板、素材和授权范围。完整预检失败、过期或漂移在首次写入前阻断；取消、未知结果、部分成功、重复领取及重启均有隔离测试，未知结果先对账。
4. 五平台产物与同一源码提交可复现，规定本地检查通过，精确候选提交的远端 CI 全绿。交叉构建不替代实际平台运行验收；正式支持仅限有证据的组合。
5. 选定宿主和 CLI 的干净安装、发现、真实查询、只读预检、人工批准/拒绝/取消、执行与恢复有精确版本和脱敏证据；真实业务写入、安装、提交、推送和发布按授权边界执行。
6. 发布说明来自对应 Changelog 段，明确预发布身份、支持范围、已知限制、状态备份/恢复及回退条件。GitHub Release 标记为 prerelease，并不作为 latest 正式版。
